# Foreman v1.1.0

Foreman v1.1.0 expands provider and installation support while refining the
web and Android experience for long-running managed sessions. It is the first
release intended to exercise the verified update paths introduced in v1.0.4.

## Highlights

- Supports Codex-only, Claude Code-only, and dual-provider Linux installations.
  Fresh installation requires at least one usable provider rather than Codex
  specifically, and preserves explicit provider choices across reinstalls.
- Adds a secure one-command Linux bootstrapper that resolves a complete stable
  GitHub release, pins Foreman's signing identity, verifies the signed checksum
  manifest and archive, rejects unsafe payloads, and delegates to the bundled
  transactional installer without using `sudo`.
- Treats a provider as task-usable only when it is both enabled and available.
  Unavailable providers remain visible in Settings for diagnosis but disappear
  from account usage, new-session choices, and other task-facing controls.
  Upgrade reconciliation disables and unchecks stale provider choices when
  their required host runtime is absent.
- Reduces misleading failed-command noise by grouping completed nonzero command
  and tool activity in Focused mode while preserving exact outcomes and full
  chronological detail when expanded.
- Removes the persistent active-turn configuration helper while retaining route
  locks and accessible per-control explanations.

## Install and update

New Linux installations can use:

```sh
curl -fsSL https://raw.githubusercontent.com/mkaltner/foreman/main/scripts/install-foreman.sh | sh
```

An inspect-before-run workflow is documented in the installation guide.

Linux installations already on v1.0.4 can check and install this release with:

```sh
foreman update --check
foreman update
```

Authorized full-access web and Android clients can initiate the same server
update from Settings → About. Android v1.0.4 can download and verify the
v1.1.0 APK there before handing it to Android's system installer for explicit
confirmation.

## Release artifacts

The release contains exactly five custom assets:

- `foreman-linux-v1.1.0.tar.gz`
- `foreman-v1.1.0.apk`
- `SHA256SUMS`
- `SHA256SUMS.sig`
- `foreman-release-cert.pem`

Verify the detached manifest signature and both payload checksums before manual
installation. The tagged workflow repeats release metadata, signer, archive,
checksum, and downloaded-payload verification before publication.

## Compatibility

- Protocol version remains v1.
- Android requires API 23 or newer and remains sideload-only.
- Android version code advances monotonically from 11 to 12.
- The Android application ID and signing-certificate fingerprint are unchanged.
- Server updates preserve configuration, paired-client state, provider choices,
  and durable session metadata, with rollback retained until activation is
  healthy.
- Existing sessions from a temporarily unavailable provider retain their
  identity and cached history without exposing unusable provider actions.
