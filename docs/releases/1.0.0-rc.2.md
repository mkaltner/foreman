# Foreman v1.0.0-rc.2

This is the corrected first buildable candidate for Foreman 1.0. The earlier
`v1.0.0-rc.1` workflow stopped at tag validation because its commit still
declared `0.1.0-alpha.6`; it produced no release artifacts. Published tags are
immutable, so this candidate advances to `rc.2`.

## Highlights

- Establishes protocol v1 and documented state-preserving Linux upgrades as the
  intended Foreman 1.x compatibility contract.
- Provides Android and web control of Codex sessions, including prompt, steer,
  interrupt, image input, approvals, structured input, model, reasoning, and
  access selection.
- Adds bounded client-local multi-host overviews plus host-scoped monitoring,
  search, conversations, and notifications.
- Adds Android and web host dashboards, focused/full activity-detail controls,
  and predictable Android Back navigation between dashboard and overview.
- Preserves command/tool history and session state across reconnect without
  replaying prompts or control operations.
- Aligns Linux, web, and Android metadata at `1.0.0-rc.2`, retains protocol v1,
  and advances Android to version code 8.

## Install and upgrade

Verify `SHA256SUMS` before using either release asset. Linux users can install
from the tagged archive or a verified tag checkout and rerun `./install.sh`.
The transactional installer preserves configuration, paired-client state, and
tokens while replacing the installed payload, and restores the previous
payload if activation fails.

Android users can install the signed `foreman-v1.0.0-rc.2.apk` over the prior
alpha to preserve encrypted saved-host tokens. Confirm version name
`1.0.0-rc.2`, version code 8, and signing certificate SHA-256
`80d479d1a8f9f038c6977a1cfb68a2b45c3117492c364620e48babebf1810ad3`.

## Compatibility and limitations

- Protocol version remains 1; see `docs/compatibility.md` for the intended 1.x
  support and upgrade policy.
- Direct TCP and HTTP are authenticated but unencrypted. Use a trusted LAN,
  private overlay, or trusted reverse proxy. Foreman does not terminate TLS.
- Android remains sideload-only. Chrome and Firefox are the intended supported
  browsers for 1.0; Edge remains best-effort.
- Multi-host overview data is bounded and client-local. Search, conversations,
  active monitoring, and notifications remain host-scoped.
- Desktop co-presence requires shared-attach mode. Fallback mode is an
  independent runtime.
- Stable promotion remains subject to the gates in
  `docs/acceptance-v1.0.0.md`, including physical-device, two-host, browser,
  HTTPS-notification, upgrade/rollback, and dependency-license evidence.

## Rollback

For Linux, unpack or check out the previously verified release and rerun its
`install.sh`; configuration and paired-client state remain in their existing
user directories. Android cannot downgrade in place to a lower version code.
