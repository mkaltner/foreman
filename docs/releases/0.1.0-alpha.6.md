# Foreman v0.1.0-alpha.6

This alpha is a release candidate, not a production-readiness claim. It focuses
on multi-host visibility, structured input and approval handling, safer host
operations, notification behavior, reconnect reconciliation, and packaging
checks added since `v0.1.0-alpha.5`.

## Highlights

- Adds bounded client-side multi-host overviews and host switching on Android
  and web while keeping tokens and transcripts scoped to each host.
- Adds verified structured user-input cards, including zero-field MCP
  confirmations, alongside the existing approval flow.
- Preserves command/tool history and session recency after refresh and
  reconnect, without replaying prompts or controls.
- Adds opt-in browser notification preferences and safer, disabled-by-default
  remote Foreman restart and sanitized diagnostics.
- Aligns Linux, web, and Android version metadata at `0.1.0-alpha.6`, retains
  protocol v1, and advances Android to version code 7.
- Strengthens tag, signing-certificate, APK metadata, web-asset, archive,
  checksum, install, upgrade, and rollback checks.
- Bounds service shutdown below systemd's stop deadline so an unresponsive
  client cannot force an unbounded install/restart wait.

## Install and upgrade

After the release is published, verify `SHA256SUMS` before using either asset.
Linux users can install from the tagged archive or a tag checkout and rerun
`./install.sh`. The transactional installer preserves
`~/.config/foreman/foreman.env` and `~/.local/state/foreman`, including paired
clients, while replacing the installed payload and removing obsolete files.

Android users must install the signed `foreman-v0.1.0-alpha.6.apk` over the
existing app to preserve encrypted host tokens. Confirm version name
`0.1.0-alpha.6`, version code 7, and signing certificate SHA-256
`80d479d1a8f9f038c6977a1cfb68a2b45c3117492c364620e48babebf1810ad3`.

## Compatibility and limitations

- Protocol version remains 1. Alpha compatibility is not guaranteed beyond the
  operations documented in `docs/protocol.md`.
- Direct TCP and HTTP are authenticated but unencrypted. Use a trusted LAN or
  private overlay; HTTPS notifications require a trusted same-origin proxy.
- Multi-host overview data is bounded, client-local, and may be stale. Search,
  conversations, active monitoring, and notifications remain host-scoped.
- Desktop co-presence exists only in shared-attach mode. Fallback mode is an
  independent runtime and must not be reported as shared Desktop proof.
- Android remains sideload-only. Browser support remains experimental.
- Complete physical-device, Chrome/Firefox/Edge, HTTPS-notification, and
  dependency-license validation must be recorded before this candidate is
  tagged or published.

## Rollback

Linux rollback means checking out or unpacking the previously verified release
and rerunning its `install.sh`; configuration and paired-client state remain in
their existing user directories. Android rollback is not supported in place
because Android rejects lower version codes; restore a device backup or
uninstall/reinstall only if losing app-local host tokens is acceptable.
